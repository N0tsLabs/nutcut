# 选题、素材与可行性

> 这是每个项目开始前的第 0 步。没有 `brief.json`，不要写 `script.json`。

---

## 1. 先收素材

用户可能给：

- 照片
- 视频片段
- 录音
- 文档 / 链接
- 只给一句话方向

用：

```bash
node bin/import.mjs --project projects/<id> --file <path> --analysis "画面内容、人物、光线、可用场景"
```

文件进入 `projects/<id>/assets/imported/`，记录进入 `imports.json`。

**分析素材时要回答：**

- 画面里有什么？人物、场景、产品、文字
- 光线、色调、景别
- 能对应文案的哪一句
- 有没有版权 / 肖像 / 隐私风险
- 哪些素材不可用或需要补拍

没有素材时，也要在 `brief.json` 里写清楚「无用户素材，使用生成图片 / 模板画面」。

---

## 2. 选题

`brief.json` 至少要回答：

- **主题**：这条片子到底讲什么
- **受众**：谁看，他们在什么场景看
- **角度**：为什么现在讲、和别的视频有什么不同
- **形式**：30 秒说明 / 60 秒故事 / 竖屏口播 / 图文动画
- **模板**：用哪套视觉模板

判断选题是否值得做：

1. 一句话能不能说清楚
2. 有没有具体画面
3. 用户是否真的关心
4. 30 秒内能不能讲完
5. 有没有事实 / 版权 / 肖像风险

---

## 3. 可行性评分

`feasibility.score` 用 0–10：

| 分数 | 含义 |
|---:|---|
| 9–10 | 选题清楚、素材齐、画面可做、风险低 |
| 7–8 | 可以做，但有一两个点需要补 |
| 5–6 | 方向成立，但素材或表达需要重做 |
| 3–4 | 风险较高，建议换角度 |
| 0–2 | 不建议做 |

`feasibility.risks` 至少写 2 条，例如：

- 30 秒讲不完
- 缺少真实画面
- 事实无法核实
- 音乐 / 图片版权
- 用户素材画质不够
- 题材同质化

`feasibility.decision`：

- `go`：可以做
- `pause`：先补资料 / 素材
- `drop`：放弃

---

## 4. 图片计划

`imagePlan` 每项对应一个场景：

```json
{ "scene": "s1", "prompt": "具体画面描述", "status": "待生成" }
```

要求：

- 画面描述具体到主体、环境、光线、构图、色调
- 和模板 `stylePrompt` 一致
- 不要写版权角色、真实明星、品牌 logo
- 生成后把 status 改成 `已生成`，并在 sidecar 里记录

---

## 5. 模板

模板在 `templates/`，先读 `template.json`：

- `palette`：配色
- `typography`：字重和字号
- `motion`：转场和节奏
- `stylePrompt`：给文案 / 生图 / 画面的统一风格描述

选定后写入：

- `project.template`
- `script.template`
- `brief.template`

Agent 后续写文案、生图、检查画面，都以这个模板为准。

---

## 6. 用户确认

把下面几项给用户确认后，才进入文案：

- 主题
- 受众
- 角度
- 可行性结论
- 模板
- 素材是否够用

用户可以直接在 Agent 对话里说，也可以在中控台项目详情页右侧「问题记录」写。内容会进 `issues.json`，Agent 下次必须先读。
